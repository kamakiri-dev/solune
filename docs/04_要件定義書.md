# SOLUNE 要件定義書

- 版：0.8（7章まで確定）
- このファイルはリポジトリの `docs/requirements.md` に置き、そちらを正本にする。

## 書き方のルール
- 画面と要件には ID を付ける。頭の文字は英語の頭文字から取る。
  | 頭の文字 | 意味 | 例 |
  |---|---|---|
  | `S-` | Screen（画面） | `S-HOME`（ホーム画面） |
  | `F-` | Functional（機能要件：アプリが何をするか） | `F-HOME-03`（ホームの機能要件の3番目） |
  | `NF-` | Non-Functional（非機能要件：速さ・安全・品質など、どのくらいよくするか） | `NF-PRIV-02`（プライバシーの非機能要件の2番目） |
- 完了条件は「〜のとき、〜になる」の箇条書きで書く。そのまま TDD のテストケースになる粒度にする。
- 7章の変換ルールは、入力 → 出力の例の表で書く。
- フェーズ2の機能は 4章に一覧として並べるだけにし、要件は書かない。
- **例に出てくる日付・時刻は、すべて架空のもの**で、実在の日付や地点を表すものではない。日付が必要な例では、**今日を 1月10日** とする。日の出・日の入りの例は、切りのいい時刻（6:00・17:00）にする。

## 1. はじめに

### 1.1 目的
- Flutter の入門（TODOアプリ）の次の「初級」の題材として、天気アプリを作る。
- 次の学習テーマを、それぞれ一度は実際に使う。
  | テーマ | このアプリでの使いどころ |
  |---|---|
  | API通信 | Open-Meteo から予報を取り、JSON をモデルに変換する |
  | 状態管理（Bloc） | Cubit から始め、HydratedBloc で予報とお気に入りを保存する |
  | 描画（CustomPainter） | 24時間ダイヤル（空の色・雨の弧・針） |
  | ジェスチャー | 針のドラッグ、縦・横のスワイプ |
  | TDD | 変換ロジック・リポジトリ・Bloc はテストを先に書く |
- 作ったものは GitHub で公開し、ポートフォリオにする。

### 1.2 コンセプト
**「1日を時計で読む天気アプリ」**
数字の一覧ではなく、円の形で「いつ・何が起きるか」がひと目でわかる。

迷ったときは、このコンセプトに近いほうを選ぶ。「天気を判断に変える」（暮らしカード）と「触って楽しい」（演出）は、あとで足すものとして扱う。

アプリ名の SOLUNE は、SOL（太陽）と LUNE（月）を合わせた造語。ダイヤルの外周（昼と夜の空）と、中央の天気マーク（昼は太陽、夜は月）を表す。

### 1.3 完成の基準（MVP）
| 種類 | 基準 |
|---|---|
| 主な基準 | 自分が毎朝2週間、ほかの天気アプリを開かずに使い続けられる |
| 確認項目 | 1.1 の学習テーマを、すべて一度ずつ使えている |

## 2. 背景

既存の天気アプリには、次の不満がある。

| 不満 | 解決のしかた | いつやるか |
|---|---|---|
| 降水確率や降水量が直感的にわからない | 数字ではなく、雨の時間帯と強さを、ダイヤルの弧と短い言葉で見せる | MVP |
| 気温だけでは服装を決められない（風・日差し・湿度が影響する） | 服装ページで、昼間と朝晩それぞれの平均気温に合った服をイラストで見せ、朝晩が冷える日・風が冷たい日・蒸し暑い日はひと言の補足を添える。ダイヤルの中央に風速を出す | MVP |
| 予報の精度 | 日本向けのモデルを選べるか、予報の当たりやすさを見せられるかを調べる | 調査してから決める（フェーズ2の候補） |

補足：Open-Meteo のモデルは指定しない（Best Match）。日本では、気温・降水量などに気象庁の MSM モデルが優先して使われる。モデルを指定すると降水確率が取れなくなるため（詳しくは 7章）。

## 3. 利用者と使い方

### 3.1 利用者
- 使うのは開発者本人だけ。
- 毎朝使う端末は Android。
- ストアでの公開はフェーズ2以降の目標。MVP では審査やプライバシーポリシーは考えない。

### 3.2 主な使い方
| 場面 | したいこと | 主に見るところ |
|---|---|---|
| 朝、家を出る前 | 雨が降るか、降るならいつか。気温はどのくらいか | 今日のダイヤル（雨の弧・針）、ダイヤルの下の2行 |
| 前日の夜 | 明日の天気と服装を決める | 明日のダイヤル、明日の服装ページ |

## 5. 画面と遷移

### 5.1 画面一覧（MVP）
| ID | 画面 | 役割 |
|---|---|---|
| S-HOME | ホーム（今日のダイヤル） | 1日の天気を時計の形で読む。今日と明日を切り替える |
| S-WEAR | 服装 | その日の服装の目安を、イラストとひと言で見せる |
| S-WEEK | 週間 | 7日間をざっと見る。出典・ライセンスのリンクを置く |
| S-LOC | 地点 | 現在地とお気に入りの管理、地名での検索 |
| S-LICENSE | ライセンス | Flutter 標準の `showLicensePage` |

### 5.2 遷移
```
            横スワイプ（地点の切り替え。ホームだけ）
   [現在地] ⇄ [お気に入り1] ⇄ [お気に入り2] ⇄ …
       │
   S-HOME ──右上の検索ボタン──▶ S-LOC ──地点をタップ──▶ その地点の S-HOME
     ⇅ 縦スワイプ
   S-WEAR
     ⇅ 縦スワイプ
   S-WEEK ──「ライセンス」──▶ S-LICENSE
          ──出典・規約のリンク──▶ 外部ブラウザ（Open-Meteo）
```

| 起点 | 操作 | 行き先 |
|---|---|---|
| S-HOME | 上にスワイプ | 同じ地点の S-WEAR（日はホームのタブに合わせる） |
| S-WEAR | 上にスワイプ | 同じ地点の S-WEEK |
| S-WEAR | 下にスワイプ | 同じ地点の S-HOME |
| S-WEEK | 下にスワイプ | 同じ地点の S-WEAR |
| S-HOME | 横にスワイプ | 前後の地点の S-HOME（上部のドットで今の位置を表示） |
| S-HOME | 「今日｜明日」のタブ | 同じ画面のまま、ダイヤルと下の表示を切り替える |
| S-HOME | 右上の検索ボタン | S-LOC |
| S-HOME（位置情報がオフのカード） | 「地名で探す」 | S-LOC |
| S-HOME（位置情報がオフのカード） | 「設定を開く」 | 端末のアプリ設定 |
| S-LOC | 地点をタップ | その地点の S-HOME（横スワイプのページもその地点に合わせる） |
| S-LOC | 戻る | 元の地点の S-HOME |
| S-WEEK | 「天気データ：Open-Meteo.com（CC BY 4.0）」 | Open-Meteo のサイト（外部ブラウザ） |
| S-WEEK | 「Open-Meteo の利用規約」 | Open-Meteo の利用規約のページ（外部ブラウザ） |
| S-WEEK | 「ライセンス」 | S-LICENSE |

### 5.3 遷移で決めたこと
- **今日／明日の切り替え**：ダイヤルの上に「今日｜明日」のタブを置く。横・縦のスワイプはほかの操作に使っているため、スワイプにはしない。中央のタップ（針を今に戻す）とも区別しやすい。
- **服装ページ**：縦スワイプの2枚目。日はホームのタブに合わせる（前日の夜に「明日」にして上にスワイプすれば、明日の服装が見られる）。
- **服装ページ・週間に出す地点**：ホームで表示中の地点。上部に地点名を出す。横スワイプは使わない（地点を変えるときはホームに戻る）。
- **地点の画面で地点をタップしたとき**：その地点のホームに移る。

## 7. データと変換ルール

### 7.1 Open-Meteo から取る項目と、時刻の扱い
- モデルは指定しない（Best Match）。`jma_seamless` などを指定すると降水確率がすべて null になるため。
- 降水確率は、常にアンサンブルモデル（約27km）から計算される。気温・降水量などとは別のモデルなので、食い違うことがある。
- 気象庁モデルの天気コードには、雷と霧が出ない。
- 風速は `wind_speed_unit=ms` を付けて m/s で取る（初期設定は km/h）。
- `past_days=1` を付けて、昨日の分も取る（2行目の「昨日との比較」に使う）。
- **`timezone=auto` を付ける。** アプリの中の時刻（ダイヤルの時刻、「今」の印、針の初期位置、日の出・日の入り、今日／明日の区切り）は、すべて**その地点の時間**で扱う。

| 種類 | 項目 |
|---|---|
| hourly | `temperature_2m`, `apparent_temperature`, `precipitation`, `precipitation_probability`, `weather_code`, `wind_speed_10m` |
| daily | `temperature_2m_max`, `temperature_2m_min`, `precipitation_sum`, `precipitation_probability_max`, `weather_code`, `sunrise`, `sunset` |
| そのほか | `utc_offset_seconds`（その地点の時刻と世界標準時のずれ） |

#### その地点の時刻の持ち方
- 時刻は**その地点の壁掛け時計に出ている時刻**として扱い、どの時間帯かの情報は持たせない。予報の時刻（`2026-01-10T08:00` など）は、返ってきた文字のまま読む。
- **その地点の現在時刻 ＝ 世界標準時の現在時刻 ＋ `utc_offset_seconds`**。海外の地点を開いたときも、ダイヤルの「今」はその地点の現在時刻を指す。
- 現在時刻は外から渡せる作り（`Clock`）にする（テストで「今」を差し替えるため）。

#### 例（そのままテストケースにする）
| 世界標準時の現在時刻 | utc_offset_seconds | その地点の現在時刻 |
|---|---|---|
| 1/10 8:57 | 32400（東京） | 1/10 17:57 |
| 1/10 8:57 | 0（ロンドン） | 1/10 8:57 |
| 1/10 20:00 | 32400（東京） | 1/11 5:00（日付も変わる） |
| 1/10 3:00 | −18000（ニューヨーク） | 1/9 22:00（日付が前に戻る） |

### 7.2 1日の区分（朝・昼間・晩）
- 服装と2行目の判断には、1日を次の3つに分けた区分を使う。区間は**始まりの時刻を含み、終わりの時刻は含まない**（7.8 と同じ）。
  | 区分 | 時間 | 使う1時間ごとの値 |
  |---|---|---|
  | 朝 | 5〜9時 | 5・6・7・8時 |
  | 昼間 | 9〜18時 | 9〜17時 |
  | 晩 | 18〜23時 | 18〜22時 |
- 0〜5時と23時は、外に出ることが少ないので、どの区分にも入れない。
- **外にいる時間帯**＝朝・昼間・晩を合わせた 5〜23時。
- **朝晩**＝朝と晩を合わせたもの。朝晩の平均気温は、朝と晩の値（9個）をまとめて平均する（朝と晩の気温はおおむね近く、服装の段階が変わるほどの差は出にくいため）。
- 区切りの時刻は、どれも設定できる値にする。

#### 例（そのままテストケースにする）
| 時刻 | 区分 |
|---|---|
| 4:00 | なし |
| 5:00 | 朝 |
| 8:00 | 朝 |
| 9:00 | 昼間 |
| 17:00 | 昼間 |
| 18:00 | 晩 |
| 22:00 | 晩 |
| 23:00 | なし |

| 1時間ごとの気温 | 昼間の平均 | 朝晩の平均 |
|---|---|---|
| 朝（5〜8時）がすべて10°、昼間（9〜17時）がすべて18°、晩（18〜22時）がすべて12° | 18.0° | 11.1°（(10×4＋12×5)÷9） |

#### 設定できる値
| 値 | 初期値 |
|---|---|
| 朝の始まり | 5時 |
| 昼間の始まり（朝の終わり） | 9時 |
| 晩の始まり（昼間の終わり） | 18時 |
| 晩の終わり | 23時 |

### 7.3 服装ページ（S-WEAR）
**位置づけ：本当に軽い提案。** 寒がり・暑がりなど人によって違うので、こだわらない。しくみはできるだけ単純にする。

#### 決め方
1. **昼間**の平均気温で昼間の服装の段階を、**朝晩**の平均気温で朝晩の服装の段階を決める（区分は 7.2）。
2. 見せ方：
   - 2つが**同じ段階**なら、1つにまとめる：「一日中 長袖シャツ」。イラストは1枚。
   - **違う段階**なら、2つ並べる：「昼間：長袖シャツ／朝晩：カーディガン・薄手の羽織り」。イラストは昼間を大きく、朝晩を小さく出す。
   - 仮の絵は、段階 → 画像の6枠をそのまま使い回す（絵は増やさない）。
3. 次の条件に当てはまるときだけ、イラストの下に**補足を1つだけ**添える。複数当てはまるときは、上のものを優先する。
   | 優先 | 条件 | 補足の言葉 |
   |---|---|---|
   | 1 | 朝晩の段階が、昼間より寒い段階 | 「朝晩は冷えるので、脱ぎ着しやすい服がよさそうです」 |
   | 2 | 外にいる時間帯（5〜23時）の平均の体感温度が平均気温より3°以上低く、いちばん強い風速が5m/s以上 | 「ただ、冷たい風で気温より寒く感じそうです」 |
   | 3 | 外にいる時間帯の平均の体感温度が平均気温より3°以上高い | 「ただ、蒸し暑く感じそうです」 |
   - 1は、すぐ上に朝晩の服装が出ているので、服の名前は言わず、着方（朝の服のまま出て、昼間に1枚脱ぐ）を言う。
   - 朝晩のほうが昼間より暖かい段階の日（まれ）は、1を出さない。
4. 補足があっても、服装の段階は変えない（補足は言葉だけ）。

#### 服装の段階
ウェザーニュースの「気温別オススメの服装」（体感報告の分析による目安）を、5°ずつにならしたもの。

| 平均気温 | 服装 |
|---|---|
| 25°以上 | 半袖 |
| 20〜25°未満 | 長袖シャツ |
| 15〜20°未満 | カーディガン・薄手の羽織り |
| 10〜15°未満 | セーター・トレンチコート |
| 5〜10°未満 | 冬物コート |
| 5°未満 | ダウンコート |

#### 例：段階と見せ方（そのままテストケースにする）
| 昼間の平均気温 | 朝晩の平均気温 | 表示 |
|---|---|---|
| 22° | 21° | 「一日中 長袖シャツ」（同じ段階なので1つにまとめる） |
| 22° | 17° | 「昼間：長袖シャツ／朝晩：カーディガン・薄手の羽織り」 |
| 25.0° | 20.0° | 「昼間：半袖／朝晩：長袖シャツ」（区切りちょうどは上の段階） |
| 12° | 4.9° | 「昼間：セーター・トレンチコート／朝晩：ダウンコート」 |

#### 例：補足（そのままテストケースにする）
| 昼間の段階 | 朝晩の段階 | 平均気温（5〜23時） | 平均の体感温度 | いちばん強い風速 | 補足 |
|---|---|---|---|---|---|
| 長袖シャツ | カーディガン・薄手の羽織り | 19° | 19° | 2m/s | 「朝晩は冷えるので、脱ぎ着しやすい服がよさそうです」 |
| 長袖シャツ | 長袖シャツ | 22° | 22° | 2m/s | なし |
| セーター・トレンチコート | ダウンコート | 8° | 4° | 7m/s | 朝晩の補足だけ（優先1が勝つ） |
| セーター・トレンチコート | セーター・トレンチコート | 12° | 8° | 7m/s | 「ただ、冷たい風で気温より寒く感じそうです」 |
| セーター・トレンチコート | セーター・トレンチコート | 12° | 8° | 3m/s | なし（風が弱い） |
| 半袖 | 半袖 | 27° | 31° | 2m/s | 「ただ、蒸し暑く感じそうです」 |
| 長袖シャツ | 半袖（朝晩のほうが暖かい） | 23° | 23° | 2m/s | なし |

#### 設定できる値
| 値 | 初期値 |
|---|---|
| 服装の段階の区切り | 25 / 20 / 15 / 10 / 5° |
| 体感の補足を出す差 | 3° |
| 「風が強い」とする風速 | 5m/s |

### 7.4 ホームの2行目：1日のプチ情報
- 1行目＝「いつ」（針を合わせた時刻の雨の様子。針で変わる。7.7）。2行目＝「どんな日か」（1日を通しての傾向や判断。針では変わらない）。
- 次の候補のうち、条件に当てはまるものを**優先順に最大2つ**、1文か2文で出す。
- 口調は天気予報のように「〜でしょう」「〜そうです」にそろえる。
- 明日のタブのときは、同じしくみで出し、「昨日より」を「今日より」に言い換える。
- 前の日のデータがないとき（保存データが古いときなど）は、「昨日との比較」だけを候補から外す。

| 優先 | 種類 | 条件 | 文 |
|---|---|---|---|
| 1 | 傘の要否 | 外にいる時間帯（5〜23時。7.2）に、雨の弧がある時間が1つでもある | 「日中に雨が降るので、傘が必要でしょう」 |
| 2 | 昨日との比較 | **昼間**（9〜18時。7.2）の平均気温が、前の日の昼間より3°以上高い／低い | 「昨日より暖かい一日になるでしょう」／「昨日より寒い一日になるでしょう」 |
| 3 | 寒暖差 | その日の最高気温と最低気温の差が10°以上 | 「昼と夜の気温差が大きいでしょう」 |
| — | 何もない日 | 1〜3のどれにも当てはまらない | 「穏やかな一日になりそうです」 |

#### 例（そのままテストケースにする）
| 外にいる時間帯に雨の弧 | 前の日との昼間の平均気温の差 | 最高−最低 | タブ | 出す文 |
|---|---|---|---|---|
| あり | −4° | 6° | 今日 | 「日中に雨が降るので、傘が必要でしょう。昨日より寒い一日になるでしょう」 |
| なし | +3.0° | 12° | 今日 | 「昨日より暖かい一日になるでしょう。昼と夜の気温差が大きいでしょう」（3°ちょうどは当てはまる） |
| あり | +1° | 11° | 今日 | 「日中に雨が降るので、傘が必要でしょう。昼と夜の気温差が大きいでしょう」 |
| あり | +5° | 12° | 今日 | 傘と昨日との比較の2つだけ（寒暖差は出さない） |
| なし | +2° | 8° | 今日 | 「穏やかな一日になりそうです」 |
| なし | −3° | 5° | 明日 | 「今日より寒い一日になるでしょう」 |
| なし | （前の日のデータなし） | 12° | 今日 | 「昼と夜の気温差が大きいでしょう」 |
| 4時だけにあり（区分の外） | +1° | 6° | 今日 | 「穏やかな一日になりそうです」 |

#### 設定できる値
| 値 | 初期値 |
|---|---|
| 昨日との比較を出す差 | 3° |
| 寒暖差を出す差 | 10° |
| 出す数の上限 | 2 |

### 7.5 ダイヤルの中央の風速
- 針の時刻の風速を「風 6m/s」の形で出す（小数は四捨五入）。
- 風向きは出さない。

### 7.6 天気マーク

### 7.7 雨：降水量の段階・雨の弧・ホームの1行目

#### 考え方
- **雨の弧は、予想降水量で描く。** 降水量は気象庁のモデル（日本向けで細かい）から来るので、雨の時間帯を見るのに向いている。
- 降水確率は、**降水量が0mmでも「降るかもしれない」時間**を見せるためだけに使う（「かすか」の弧）。基準を50%と高めにして、外れた予報の弧が出すぎないようにする。

#### 降水量の段階
| 1時間の降水量 | 段階 |
|---|---|
| 0.1mm未満 | なし |
| 0.1〜1mm未満 | 弱い（ぽつぽつ） |
| 1〜5mm未満 | 中くらい（しっかり） |
| 5mm以上 | 強い |

#### 雨の弧の決め方
1. 降水量が0.1mm以上なら、降水量の段階に合わせて描く（降水確率は見ない）。弱い＝薄い、中くらい＝中くらい、強い＝濃い。
2. 降水量が0.1mm未満で、降水確率が基準（50%）以上なら、**かすか**（いちばん薄い弧）で描く。
3. それ以外は描かない。降水確率が null のときは、基準未満として扱う。

#### 例（そのままテストケースにする）
| 降水確率 | 降水量 | 弧 |
|---|---|---|
| 10% | 0.1mm | 薄い（確率が低くても、量があれば描く） |
| 60% | 0.9mm | 薄い |
| 20% | 1.0mm | 中くらい |
| 40% | 5.0mm | 濃い |
| 49% | 0.0mm | 描かない |
| 50% | 0.0mm | かすか（50%ちょうどは描く） |
| null | 0.0mm | 描かない |
| null | 2.0mm | 中くらい |

#### ホームの1行目（針を合わせた時刻の雨の様子）
- 1行目は**雨のことだけ**を言う（気温・風は中央に数字で出ているため）。
- 針の時刻の弧に合わせて、次の文を出す。

| 弧 | 1行目の文 |
|---|---|
| 描かない | 「雨の心配はなさそうです」 |
| かすか | 「雨が降るかもしれません」 |
| 薄い | 「ぽつぽつ降りそうです」 |
| 中くらい | 「しっかり降るので、傘が必要でしょう」 |
| 濃い | 「強い雨になりそうです」 |

#### 設定できる値
| 値 | 初期値 |
|---|---|
| 降水量の段階の区切り | 0.1 / 1 / 5mm |
| かすかの弧を描く降水確率の基準 | 50% |

### 7.8 空の時間帯（ダイヤルの外周の色）
- 日の出・日の入りの時刻（daily の `sunrise` / `sunset`）と、幅（初期値30分。設定できる値）から、時刻ごとの時間帯を決める。
  | 時間帯 | 範囲 |
  |---|---|
  | 夜 | 日の入り＋幅 〜 日の出−幅 |
  | 明け方 | 日の出−幅 〜 日の出＋幅（紺 → 薄い橙 → 空色） |
  | 昼 | 日の出＋幅 〜 日の入り−幅 |
  | 夕方 | 日の入り−幅 〜 日の入り＋幅（空色 → 橙 → 紺） |
- 区間は**始まりの時刻を含み、終わりの時刻は含まない**。
- 明け方・夕方では、区間の中の**進み具合**（0〜1）も出す。色はこの進み具合で少しずつ変える。
- テストでは時間帯と進み具合までを確かめる。色そのものは確かめない。
- 明日のダイヤルには、明日の日の出・日の入りを使う。

#### 例（日の出 6:00・日の入り 17:00・幅30分の日。そのままテストケースにする）
| 時刻 | 時間帯 | 進み具合 |
|---|---|---|
| 5:29 | 夜 | — |
| 5:30 | 明け方 | 0.0 |
| 6:00 | 明け方 | 0.5 |
| 6:30 | 昼 | — |
| 16:29 | 昼 | — |
| 16:30 | 夕方 | 0.0 |
| 17:00 | 夕方 | 0.5 |
| 17:30 | 夜 | — |

### 7.9 週間の気温の幅バー
- 週の最低＝7日間の最低気温のうちいちばん低い値、週の最高＝7日間の最高気温のうちいちばん高い値。
- 棒の**始まり**＝(その日の最低 − 週の最低) ÷ (週の最高 − 週の最低)
- 棒の**長さ**＝(その日の最高 − その日の最低) ÷ (週の最高 − 週の最低)
- どちらも 0〜1 の割合で出す。画面の幅に掛けるのは描くときに行う。
- 週の最高と最低が同じとき（0で割ることになるとき）は、始まり 0・長さ 1 にする。

#### 例（そのままテストケースにする。小数第2位まで）
| 週の最低〜最高 | その日の最低〜最高 | 始まり | 長さ |
|---|---|---|---|
| 5〜20° | 8〜15° | 0.20 | 0.47 |
| 5〜20° | 5〜20° | 0.00 | 1.00 |
| 5〜20° | 12〜12° | 0.47 | 0.00 |
| 10〜10° | 10〜10° | 0.00 | 1.00（0で割らない） |

### 7.10 ダイヤルの角度と時刻
- 0時を真上の0°とし、**時計回り**に1時間＝15°、1分＝0.25°。
- 画面に触れた位置から角度を求めるときも、ダイヤルの中心から見て真上を0°、時計回りに数える。
- **吸い付き**：指で動かしているあいだと指を離したとき、針は**いちばん近い1時間**に吸い付く。ちょうど半分（x:30）は先の時刻に吸い付く。
- **23:30以降の位置は、同じ日の0時に吸い付く**（ダイヤルは円なので、23時の先は0時。明日の0時にはしない）。
- **「今」の印**：その地点の現在時刻（7.1）の正確な角度に置く（1分ごとに進む）。明日のダイヤルには出さない。
- **針の初期位置**：アプリを開いたとき、ダイヤルの中央をタップしたときは、その地点の現在時刻の正確な角度に置く。表示する値は、その時刻の「時」のもの（15:42なら15時の値）。
- 今日 → 明日に切り替えたときは、針の時刻をそのまま使う。

#### 例（そのままテストケースにする）
| 入力 | 出力 |
|---|---|
| 時刻 0:00 | 0° |
| 時刻 6:00 | 90° |
| 時刻 12:00 | 180° |
| 時刻 15:42（今の印） | 235.5° |
| 角度 97°（6:28） | 6時に吸い付く |
| 角度 97.5°（6:30） | 7時に吸い付く（半分は先の時刻） |
| 角度 352.5°（23:30） | 0時に吸い付く |
| 角度 345°（23:00） | 23時 |
| 現在時刻 15:42 で開く | 針は 235.5°、表示する値は15時のもの |

### 7.11 緯度・経度の丸め
- 緯度・経度は、**小数第2位（約1km）に四捨五入**してから、API に送り、保存する。
- ちょうど半分の値（35.685 など）の結果は、テストに入れない。小数は計算機の中で誤差が出やすく、約1km単位の丸めなら、どちらになっても困らないため。

#### 例（そのままテストケースにする。東京駅付近）
| 入力 | 出力 |
|---|---|
| 35.68124 | 35.68 |
| 139.76712 | 139.77 |
| −0.12574 | −0.13 |
| 35.6 | 35.6（そのまま） |

### 7.12 自動更新の判断
- **地点ごとに判断する**（前回の取得時刻は地点ごとに持つ）。
- 判断するとき：アプリを開いたとき、ほかのアプリから戻ったとき、**横スワイプでその地点のページを開いたとき**。判断するのは表示中の地点だけで、まだ開いていない地点の分を先に取っておくことはしない。
- 更新する条件：その地点のデータが一度も取れていない、または前回の取得から30分以上たっている（「30分」は設定できる値）。
- 更新中なら、何もしない（二重に通信しない）。手動の更新（↻）も同じ。
- 開いたままのときは自動更新しない（1分ごとに「今」の印を進めるだけ）。

#### 例（そのままテストケースにする）
| その地点の前回の取得 | 今 | 更新中か | 結果 |
|---|---|---|---|
| なし | 8:00 | いいえ | 更新する |
| 7:31 | 8:00（29分後） | いいえ | 更新しない |
| 7:30 | 8:00（30分後） | いいえ | 更新する |
| 7:00 | 8:00 | はい | 何もしない |

### 7.13 保存データを使うかどうかと、予報の時刻の表示

#### 保存データを使うかどうか
- 予報の取得に失敗したとき、保存データに**表示する日**の予報が含まれていれば、古くてもそれを表示する。含まれていなければ、エラーの画面と「再読み込み」ボタンを出す。
- 今日のタブと明日のタブは、それぞれ別に判断する。
- 手動の更新（↻）で失敗したときは、表示はそのままにし、「更新できませんでした」と短く出す。

#### 例（今日が 1/10 のとき。そのままテストケースにする）
| 保存データの中身 | 表示する日 | 結果 |
|---|---|---|
| 1/9〜1/15 | 1/10（今日） | 保存データを表示する |
| 1/9〜1/15 | 1/11（明日） | 保存データを表示する |
| 1/3〜1/9 | 1/10（今日） | エラーの画面 |
| 1/4〜1/10 | 1/11（明日） | エラーの画面（今日のタブは表示できる） |
| なし（一度も取れていない） | 1/10（今日） | エラーの画面 |

#### 予報の時刻の表示
- 最後に予報を取れた時刻を「○○時点の予報」の形で出す。ふだんはアプリを開いたときに最新の予報を取るので、今日の時刻が出る。
- 取れた日が今日でないとき（電波がなくて古い保存データを見ているときなど）だけ、日付を付ける。「今日」はその地点の時間で数える。

| 最後に取れたとき（今日が 1/10） | 表示 |
|---|---|
| 1/10 7:05 | 「7:05時点の予報」 |
| 1/9 22:00 | 「昨日 22:00時点の予報」 |
| 1/8 22:00 | 「1/8 22:00時点の予報」 |
