## 進め方のルール
- Claude Code には「`docs/tasks.md` の R-02 をやって」のように、ID で頼む。
- **1タスク＝1ブランチ＝1PR。** CI（analyze と test）が通ったら main にマージする（CI ができる P-03 より前は、PR を作ってそのままマージしてよい）。
- R のタスクは TDD で進める：
  1. 完了条件の例をテストに書き、**失敗するのを確かめる**（赤）
  2. テストが通るいちばん簡単な実装を書く（緑）
  3. 読みやすく整える。テストが通ったままであることを確かめる（整理）
- 「状態」の欄は、そのタスクの PR の中で「完了」に直す（PR をマージすると main の欄も「完了」になる。main を直接書き換えないため）。並行しているブランチどうしでこの表がぶつかったら、あとからマージする PR のほうで直す。
- 区切り（マイルストーン）が終わるたびに、main にタグを付ける（例：`milestone-1`）。あとから、その区切りの時点のコードに戻って見返せるようにするため。

## 始める前に（P-01 の前に開発者が手でやること）
1. GitHub に空のリポジトリ `solune` を作り、手元に clone する。
2. 要件定義書を `docs/requirements.md`、このタスク一覧を `docs/tasks.md` として置き、main に push する（Claude Code がタスクを読めるようにするため。P-04 の一部を先にやる）。

## 並行作業のルール
- git の `worktree` を使うと、ブランチごとに別のフォルダを作り、それぞれで Claude Code を動かせる。
- **はじめは1つずつ進める。** TDD の「赤 → 緑 → 整理」の流れと、PR からマージまでの流れをつかんでから並行にする。
- 並行にするときも、**同時に進めるのは2つまで**（PR を読んで動作を確かめるのは開発者なので）。
- 同じファイルを触るタスクは、同時に進めない。R のタスクは、自分のフォルダ（`lib/rules/<ルール名>/`）の中だけで完結するように作る。
- 色・文字の大きさ・画面の文言など、アプリ全体で使うものは、A-01 で作る共有のファイル（`lib/app/theme/`）に置く。ほかのタスクは使うだけにして、書き換えない。
- 下の「並行してよい組み合わせ」の段階を守る（前の段階が全部終わってから次へ）。
